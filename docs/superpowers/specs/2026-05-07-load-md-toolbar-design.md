## 1. 背景与目标

### 1.1 背景

`MarkdownEditorView.vue` 顶栏在「下载 .md」主按钮之前，需要增加 **加载外部 Markdown** 的能力：用户可通过 **本地文件** 或 **Web URL** 将内容载入当前编辑器，并沿用现有防抖预览、sanitize、Mermaid 渲染与 localStorage 持久化管线。

### 1.2 产品目标

- 在 **「下载 .md」左侧** 增加 **`ghost-btn`「加载 .md」**。
- 点击后展开 **下拉菜单**，包含两项：
  1. **「从本地选择…」**：触发系统文件选择；选中后 **整块替换** 当前编辑器文本。
  2. **「从 URL 载入…」**：关闭下拉后打开 **对话框**（URL 输入、取消、载入）；成功则同样 **整块替换** 当前编辑器文本。
- **URL 加载**：采用 **可配置的同源拉取通道**，解决常见 **CORS** 限制（见第 5 节）；无法拉取时在 UI 中展示 **明确错误**。
- 行为与现有 **「载入示例」** 一致：**不** 单独做「未保存确认」弹窗。

### 1.3 非目标（首版）

- 在浏览器内对 **任意** 第三方 URL 保证 100% 可拉取（仍受目标站可用性、证书、封禁与部署侧配置影响）。
- 分段合并、diff 合并、多标签多文档。
- 取向 2：浏览器先直连 `fetch(url)`、失败再回退代理（可列为后续优化，本版 **不做**）。
- 使用第三方公共 CORS 代理服务。

### 1.4 成功标准（验收导向）

- 下拉两项均可用；本地 `.md` / `.txt` 等受 accept 约束的文件可载入并刷新预览。
- 开发环境下，通过 **Vite 开发服务器中间件** 提供的同源路径可拉取 **http/https** 公开文本资源（在约定大小与超时内）；失败时错误信息可理解。
- 生产构建：未配置远程拉取基址时，**「从 URL 载入」** 被 **禁用或灰显**，并有简短说明；配置 `VITE_MD_FETCH_BASE` 后，URL 载入指向该基址的等价接口（见 5.3）。

## 2. 术语

| 术语 | 含义 |
|------|------|
| 同源拉取 | 浏览器只请求 **当前站点来源** 下的路径，由 **服务端或开发中间件** 代为请求用户指定的远程 URL |
| `md-fetch` | 本文规定的内部 API 形态（路径常量实现时固定，见 5.2） |

---

## 3. 已确认的决策摘要

| 主题 | 决策 |
|------|------|
| URL 与跨域 | **B**：仓库内提供 **开发态** 可配置代理能力（Vite `configureServer` 中间件）；生产依赖 **可选** 环境变量指向已部署的等价接口 |
| 一级交互 | **A**：「加载 .md」+ **下拉**：「从本地选择…」「从 URL 载入…」；URL 走 **对话框** |
| 实现取向 | **取向 1**：URL 默认经 **同源 md-fetch 通道**（开发由 Vite 中间件实现）；**不做** 浏览器优先直连回退 |
| 生产 URL | **P2**：支持 **`VITE_MD_FETCH_BASE`**；**未设置或空字符串** 时等价 **P1**（禁用或灰显「从 URL 载入」并说明需服务端接口） |

## 4. 信息架构与交互细节

### 4.1 工具栏顺序

在 `MarkdownEditorView.vue` 的 `toolbar-actions` 中，相对 **「下载 .md」**：

- **左侧紧邻** 插入 **「加载 .md」**（`ghost-btn`），再保持现有 **「下载 .md」**（`primary-btn`）、**「下载 HTML」**、**「载入示例」** 顺序不变。

### 4.2 下拉菜单

- **展开/收起**：点击「加载 .md」切换；点击页面其他区域或 **ESC** 关闭。
- **「从本地选择…」**：触发隐藏的 `<input type="file">`；选择文件后读取内容并关闭下拉（若实现上需保持菜单关闭，可先关菜单再程序化触发 input）。
- **「从 URL 载入…」**：先关闭下拉，再打开 **URL 对话框**。

### 4.3 本地文件

- **`accept`**：至少包含 `.md`、`.markdown`、`.txt`，以及 MIME `text/markdown`、`text/plain`（实现时可合并为浏览器可识别的字符串）。
- 使用 **`FileReader.readAsText`**，按 **UTF-8** 解释。
- 成功后：**同时** 更新 `source` 与 **`debouncedSource`**（与 `loadSample()` 对齐），使预览尽快刷新；`persistSource` 仍由既有 **Markdown 管线成功路径** 写入 `localStorage`（与现行一致）。
- 可选：**单文件体积上限**（若设定）：超限时报错，不写编辑器；上限数值在实现计划中写死。

### 4.4 URL 对话框

- 控件：可读写的 URL 文本框、「取消」「载入」。
- **ESC** 关闭对话框；焦点管理满足基本可用即可（不要求完整焦点陷阱）。
- 校验：用户提交前 **必须为绝对 URL**，且 scheme 为 **`http:` 或 `https:`**；非法时 **仅提示**，不发起请求。
- 成功：**同 4.3** 更新 `source` / `debouncedSource`。
- 失败：**对话框内** 展示简短错误文案（可与现有 `topError` 并存或收敛为一种展示方式；实现时需统一为一种 **不致重复刷屏** 的模式）。

## 5. md-fetch 通道（开发中间件与生产配置）

### 5.1 职责划分

- **开发**：由 Vite `configureServer` 中间件实现 **`GET /__md-studio/md-fetch`**，契约见 5.4。
- **生产**：由部署方在 **`VITE_MD_FETCH_BASE`** 所指源站提供 **相同 query 与响应语义** 的接口；本仓库仅规定前端如何拼接 URL（见 5.3）。

### 5.2 路径与请求形态（常量）

实现时在代码中固定 **单一路径片段**（名称可微调但必须全仓一致），例如：

- **`GET`** `/<prefix>/md-fetch?url=<encodeURIComponent(absoluteUrl)>`

其中 `<prefix>` 建议为 **`__md-studio`**，完整路径 **`/__md-studio/md-fetch`**。

- 前端在 **开发模式**（`import.meta.env.DEV`）下请求的 **基址为空**（即同源当前 dev origin）。
- 前端在 **生产模式**下：若配置了 **`import.meta.env.VITE_MD_FETCH_BASE`**（末尾无斜杠、不含 path），则请求 **`${VITE_MD_FETCH_BASE}${上述 path + query}`**；若 **未配置或为空**：**不发起 URL 载入请求**，「从 URL 载入」禁用并提示。

**说明**：部署方需自行提供与 **5.4** 行为一致的网关或后端；本仓库首版仅需 **开发中间件 + 前端拼接规则**。

### 5.3 `VITE_MD_FETCH_BASE`

| 取值 | 行为 |
|------|------|
| 未定义或空 | 「从 URL 载入」不可用（灰显 + `title`/说明） |
| 非空绝对 URL（推荐 https 源站） | 对该基址追加固定 path `/__md-studio/md-fetch?url=`… 发起 `GET` |

若生产环境无法在同一 path 挂载接口，可由部署层 **重写 path** —— 需在部署文档中单列说明（本规格不改变前端常量名，重写由网关完成）。

### 5.4 开发中间件行为（Node `fetch`）

在 **`vite.config.ts`** 的 `configureServer` 中注册 middleware，仅在 **开发服务器**生效：

| 约束 | 要求 |
|------|------|
| URL scheme | 仅允许 `http:`、`https:` |
| 超时 | **10 秒**（实现可 ±1s） |
| 响应体上限 | **2 MiB**；超出返回错误（4xx + JSON 或纯文本前缀约定，前后端对齐一种） |
| HTTP 状态 | 远端非 2xx 时转发状态或统一为 **502**，body 中带可读摘要 |
| 重定向 | 跟随 `fetch` 默认语义；若在实现中发现需限制，则在实现计划中写明 **最多 3 次** 或等价策略 |

响应正文：优先以 **文本** 形式返回远端 body，字符集处理首版可按 **UTF-8**；若 `Content-Type` 声明明显非文本，返回 **415 或 400** 级错误与用户可读说明。

### 5.5 安全（建议 / 可选后续）

首版可在规格中预留 **不推荐依赖** 的说明：在中间件中对 **RFC1918、`localhost`、`169.254.169.254` 等** 做简易拦截以降低误用型 SSRF 风险。**首版必选**仅是 **HTTPS/HTTP + 超时 + 体积上限**；私有网拦截列为 **follow-up**，在实现计划中标记为可选。

## 6. 错误处理与无障碍

- **本地**：读文件失败、空文件策略（可选：允许空字符串）、超限 —— 同一错误展示模式。
- **URL**：网络失败、超时、超限、远端 4xx/5xx、非法 scheme —— 对话框错误 +必要时 `console` 便于调试（生产可降级）。
- 键盘：**ESC** 关闭下拉与对话框。
- **`aria-expanded` / `aria-haspopup`**：为「加载 .md」与菜单关系提供适当属性。

## 7. 测试与验收清单（首版）

- 下拉打开/关闭、ESC、点击外部关闭。
- 本地选择 `.md`、`.txt`：内容替换正确，预览与持久化随后成功。
- 开发环境：`/__md-studio/md-fetch?url=` 对一公开 raw markdown URL 返回 200；`404`/`timeout`/`>2MiB` 有清晰错误。
- 生产：**无 `VITE_MD_FETCH_BASE`** 时 URL 入口不可用；配置后能对部署的等价接口发起请求并成功替换（若在 CI 不可测，可由人工在预发布环境勾选）。

自动化单测：**可选**，以中间件纯函数提取时为佳；未提取则依赖上述手动清单。
